# 자동 커밋 정책

커밋 및 push 관련 규칙을 정의한다.

## 커밋 조건

- 변경 사항이 있을 때만 commit
- 모든 테스트 통과 시에만 commit
- push는 사용자가 명시적으로 요청할 때만 수행

## Tidy First 커밋 분리

구조적 변경과 행위적 변경은 **반드시 별도 커밋**으로 분리한다.

| 변경 유형 | 커밋 타입 | 예시 |
|-----------|----------|------|
| 구조적 변경 (기능 변경 없음) | `refactor`, `style` | 변수명 변경, 파일 이동, 포맷팅 |
| 행위적 변경 (기능 변경 있음) | `feat`, `fix` | 새 기능 추가, 버그 수정 |

## 커밋 메시지 형식

커밋 메시지는 **한국어**로 작성한다.

```
<타입>: <제목>

- 변경 사항 1
- 변경 사항 2

영향 범위: <영향받는 모듈/파일>
```

## 커밋 타입

| 타입 | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 코드 리팩터링 (기능 변경 없음) |
| `style` | 코드 포맷팅, 세미콜론 누락 등 |
| `docs` | 문서 수정 |
| `test` | 테스트 코드 추가/수정 |
| `chore` | 빌드 설정, 패키지 매니저 설정 등 |

## 예시

```
feat: 게시글 삭제 기능 추가

- DELETE /api/posts/[id] 엔드포인트 구현
- 로그인된 사용자만 삭제 가능하도록 인증 미들웨어 적용
- 삭제 확인 모달 컴포넌트 추가

영향 범위: src/app/api/posts/[id]/route.ts, src/components/posts/
```

```
refactor: PostCard 컴포넌트 분리

- PostList에서 개별 카드 렌더링 로직을 PostCard로 추출
- props 인터페이스 정의

영향 범위: src/components/posts/
```
